# ثروة — نسخة مستقلة من المحفظة

نسخة مستقلة من التطبيق الأصلي، بواجهة عاجية وخضراء للكمبيوتر والموبايل. البيانات السحابية في Supabase PostgreSQL، والكود قابل للنشر عبر GitHub Pages. لا يوجد اتصال تشغيلي بـ Apps Script أو Google Sheets.

## التشغيل

يتطلب Node.js 22.

```sh
npm ci
cp .env.example .env
npm run dev
```

المشروع مربوط بـ Supabase Tharwa عبر `src/public-config.js`. يمكن تجاوز الإعدادات العامة بملف `.env`. لا تضع `service_role` أو مفتاحاً سرياً في أي متغير يبدأ بـ `VITE_`.

بدون إعداد قاعدة البيانات تظهر شاشة توضح ضرورة الربط، ويمكن اختيار تجربة غير محفوظة. وضع `?demo=1` يعمل في الذاكرة؛ لا تعتبر البيانات المستوردة فيه محفوظة، وتختفي عند إعادة التحميل.

## تجهيز Supabase

1. أنشئ مشروعاً وحدد موقع استضافة مناسباً لك.
2. في مشروع جديد، طبّق ملفات `supabase/migrations` بالترتيب. طُبّقت بالفعل على مشروع Tharwa الحالي.
3. أنشئ مستخدمك من Authentication وأوقف التسجيل العام إذا أردت استخداماً شخصياً فقط.
4. انشر الدالة `portfolio-market` بمجلدها الكامل. التحقق من الجلسة يتم داخل الدالة عبر `auth.getUser` قبل أي طلب خارجي. فحص JWT القديم في البوابة معطّل للتوافق مع مفاتيح التوقيع الحديثة؛ لا يُقبل طلب بدون جلسة صحيحة.
5. يمكن إضافة `FMP_API_KEY` ضمن أسرار الدالة للقوائم المالية. يدعم التطبيق أيضاً مفتاح المالك الموجود في إعداداته الخاصة، كما كان في النسخة الأصلية.
6. أدخل عنوان المشروع والمفتاح العام في ملف البيئة. اضبط Site URL على رابط الموقع النهائي.

## الاستيراد

سجل الدخول، ثم اضغط أيقونة الرفع الصغيرة في الرأس واختر ملف Excel الأصلي. تظهر أعداد السجلات قبل الاستبدال. الاستيراد عملية واحدة، مع الاحتفاظ بالإصدار السابق في سجل القاعدة. يتم حفظ Transactions، Assets، OtherSources، Notes، Settings، Deletedtxns، النسخة الاحتياطية، ومحتوى الأوراق الأصلية الأخرى في قاعدة البيانات الخاصة.

ورقة Settings لا تحتوي صف عناوين؛ أول مفتاح فيها جزء من البيانات. لا توضع البيانات المالية أو ملف Excel ضمن المستودع أو الملفات المنشورة. احتفظ بملفك الأصلي خارج المشروع.

## النشر على GitHub

- ارفع هذا المجلد إلى مستودعك.
- الإعدادات العامة مضمنة في `src/public-config.js`؛ لا يلزم إدخال مفاتيح للنشر. متغيرات `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` اختيارية لتجاوزها.
- فعّل Pages بمصدر GitHub Actions.
- النشر يعمل عند تحديث `main`، ويمكن تشغيل `Publish portfolio` يدوياً من Actions. يلزم تفعيل Pages في إعدادات المستودع أولاً.
- تأكد من تفعيل قاعدة البيانات والدالة قبل اعتماد الموقع للاستخدام اليومي.

## البيانات والحفظ

لكل مستخدم سجل JSONB خاص داخل PostgreSQL. هذه صيغة نقل تحفظ اختلاف حقول التطبيق القديم، وليست ملفاً في GitHub. Row Level Security يعزل المستخدمين. الحفظ عبر إجراء SQL ذري يتحقق من رقم الإصدار ويحفظ آخر 50 نسخة. إذا سبق جهاز آخر بالحفظ، يتوقف الحفظ ويظهر تنبيه لتصدير التعديلات وإعادة التحميل. لا توجد مزامنة فورية تدفع التغييرات إلى شاشة مفتوحة في جهاز آخر.

المعاملات المرتبطة الجديدة تحتفظ بـ `linkedTxnId`. الروابط القديمة غير الموجودة في ملف Excel لا يمكن استنتاجها بأمان، ولم تُخمن. الحذف إلى سلة المحذوفات، واسترجاع زوج مرتبط يعيد الطرفين. يوجد أيضاً حفظ تلقائي للأصول والمصادر والملاحظات والإعدادات.

## التصميم والوظائف

الرئيسية أعيد بناؤها من التصميم المعتمد: عاجي وأخضر غامق، خطوط عربية محلية، وفقاعة مرتبطة بفئة الأصول مع حركة دخول ودعم تقليل الحركة. الصفحات التفصيلية تحتفظ بمحرك التطبيق الأصلي ووظائفه، مع تطبيق ألوان وخطوط النسخة الجديدة وإصلاح عرض الكمبيوتر. ليست كل شاشة تفصيلية قد أعيد تصميم هيكلها من الصفر.

تم الإبقاء على حسابات FIFO والأهداف والزكاة وتحليل الصناديق والملاحظات. زر التنزيل ينتج ملف XLSX حقيقياً للحركات، مع المعرّفات والعلاقة بين الحركات. لا يصدّر باقي البيانات تلقائياً.

## حالة التحقق والحدود الحالية

- `npm test`: اختبارات الاستيراد والتصدير، FIFO، الحركات المرتبطة، تعارض الحفظ، تحليل ملفات الصناديق وعقد أسعار السوق.
- `npm run build`: بناء ناجح.
- تم استيراد الملف المرفق محلياً: 120 حركة، 17 أصل، 11 مصدر، 4 ملاحظات، 17 حركة محذوفة و120 حركة احتياطية.
- طُبّقت مخططات SQL على مشروع Supabase Tharwa. نجح اختبار تحميل وحفظ داخل معاملة حية تم التراجع عنها، واختبارات PGlite لعزل المستخدمين وتعارض الحفظ واستلام الاستيراد لحساب ذي بريد موثّق فقط. الإجراءات ذات الصلاحيات المرتفعة داخل مخطط private؛ الإجراءات العامة تعمل بصلاحية المستدعي.
- اختُبرت الواجهة بمتصفح Chromium على 1536 و390 و320 بكسل، مع إضافة وتعديل وحذف واسترجاع حركة والتحقق بعد إعادة التحميل داخل وضع التجربة، ومعاينة الملاحظات. هذه تجربة متصفح وليست اختباراً على أجهزة iOS/Android فعلية.
- خدمة portfolio-market منشورة في Supabase؛ نجح طلب سعر مباشر من Yahoo. استدعاء الخدمة بحساب التطبيق وواجهات iShares وFMP تحتاج اختباراً حياً بعد تجهيز حساب التطبيق. Yahoo مستخدم كبديل مستقل للرابط السابق؛ نقاط نهايته قد تتغير أو تفرض حدوداً. يظهر غياب السعر، وتُستخدم التكلفة عند عدم وجوده. لا تُعرض أسعار تجريبية على أنها حية. حدود دفعات القوائم المالية 8 شركات لكل طلب.
- معادلات الذهب والزكاة وطريقة احتساب الأرباح مأخوذة من الكود الأصلي؛ النقل لا يمثل مراجعة مالية أو شرعية لها.
- المصدر الكبير في `public/legacy/app.js` يحتفظ بصفحات قديمة تعتمد قوالب HTML. تم تعقيم عرض Markdown للملاحظات، لكن لم يُنجز تدقيق أمني شامل لكل قوالب الواجهة القديمة. قبل إتاحة التطبيق لمستخدمين آخرين يلزم استكمال تدقيق حقول الإدخال والعرض.

راجع `docs/MIGRATION.md` للتغييرات التقنية.

مراجع إعداد الخدمات: [Supabase Auth](https://supabase.com/docs/reference/javascript/auth-signinwithpassword)، [Edge Functions](https://supabase.com/docs/guides/functions/auth)، [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## الاستيراد المجهّز وحساب التطبيق

حُفظ الملف الأصلي في جدول private.portfolio_imports، خارج واجهة Data API وبدون صلاحيات للمستخدمين. عند أول تحميل من حساب له البريد الموثّق المطابق، تنتقل نسخته إلى المحفظة الخاصة تلقائياً مرة واحدة. لا يُستبدل أي تعديل لاحق. لم يُنشأ حساب تطبيق أو كلمة مرور نيابة عن المستخدم. يمكن للمالك إنشاء حساب من Supabase > Authentication > Users > Add user، ببريده وكلمة مرور مستقلة يختارها، ثم تسجيل الدخول بها في التطبيق. حساب لوحة Supabase لا ينشئ مستخدم تطبيق تلقائياً.

آخر تدقيق أمني لم يجد تحذيرات؛ بقيت ملاحظة معلوماتية مقصودة لجدول الاستيراد الخاص: RLS بلا سياسة، حتى يُرفض وصول مستخدمي التطبيق المباشر إليه. لم يُختبر دخول المالك أو الأسعار الحية بعد، والنشر يعتمد على تفعيل استضافة GitHub Pages.
